The implementation architecture and its evidence boundary

objectKV today is a real single-range laboratory kernel composed from process-replicated authorities, a regional GCS object base, a retained txLog, and a disposable RocksDB read engine. Resident concurrency and the corrected 64 MiB cache-pressure point are cloud-admitted. The full cache curve, continuously objectifying multi-machine transactional cell, and stable workload-facing API are not yet admitted.

Architecture today

Clarity

Real mechanism, not yet a database service

The repository has the pieces and one integrated recovery and read slice. That slice can execute transactions, rebuild a replacement worker from objects plus retained history, and serve exact versioned point reads. It is still an evaluator-driven process topology rather than a deployable workload endpoint.

Read pipeline

Open and recover a resident range

  → PublicationAuthority.read(root)
  → GET and verify manifest
  → GET and verify every row segment
  → decode complete object state
  → install head + history + metadata in RocksDB

  → atomically advance data + applied cursor
  → bind snapshot at T

  → SingleRange coverage check
  → ResidentRangeEngine.snapshot(G, T)

  → MVCC history when T is older

Write and publication pipeline

Current commit path

TransactionCommand
  → commit_fenced(identity, generation)
  → transaction OpenRaft leader
  → conflict check + commit version
  → quorum-stable node journals
  → retained outcome
  → commit response
  → SingleRange catches up through commit
  → disposable RocksDB head/history/frontier flush

Current object publication path

frozen base records
  → encode indexed row segment set
  → prepare exact publication intent
  → PUT immutable data and index objects
  → PUT manifest
  → publish exact root transition
  → readers walk the named closure

not called by every SingleRange commit

The commit acknowledgement does not wait on object storage. This part matches the target architecture. The gap is lifecycle integration: the current evaluator constructs and publishes a base before the read experiment. There is no continuously running objectifier that drains committed txLog history, advances O, compacts runs, and reclaims the safe suffix while workload traffic continues.

Evaluator rule

Performance comparison requires a workload receipt

Every candidate and control now carries an evidence class. Contract proves semantics. Smoke proves wiring. Workload proves one hashed envelope containing dataset, mix, distribution, concurrency, warmup, measurement, cache state, failure schedule, limits, metrics, repeats, and matched control. A smoke or legacy receipt is invalid for performance admission.

A cell is the complete transaction domain and failure boundary. Ranges are internal placement and scaling units. Tenants may transact across ranges inside one cell. There is no cross-cell transaction in the kernel.
